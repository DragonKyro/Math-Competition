# CLAUDE.md

Conventions for this repo. Read this before adding exams, changing formats, or extending the scripts.

## What this repo is

A personal library of math-competition problems and solutions (AMC 8/10/12, AIME, extendable), organized so problems can be practiced **by exam** or **by topic**. Each problem lives in exactly one file (its exam file); topic pages are generated indexes that link into those files via heading anchors.

## Non-negotiables

- **One problem lives in exactly one place** — inside its exam `.md` under `problems/<competition>/<file>`. Never duplicate problems into a `solutions/` tree or a `topics/` tree.
- **Solutions go inside `<details><summary>Solution</summary> ... </details>`** so readers can attempt the problem without spoilers.
- **Topic pages are generated, not hand-edited.** Only the content between `<!-- AUTOGEN-START -->` and `<!-- AUTOGEN-END -->` is rewritten; the heading and description above those markers are preserved. Never paste a table outside that block.

## Exam file format

```markdown
# 2023 AIME I

## Problem 1
*Tags: probability, combinatorics*

Problem statement with $\LaTeX$ math in dollar signs.

<details><summary>Solution</summary>

**Solution 1.**

Full walkthrough.

**Answer:** $\boxed{191}$

</details>

---

## Problem 2
...
```

**Rules:**
- H1 (`# ...`) is the exam title once, at the top
- H2 (`## Problem N`) for every problem — GitHub auto-generates `#problem-N` as the anchor, which is what topic tables link to. Don't rename these headings.
- `*Tags:*` line is a single line, italicized, with lowercase hyphenated slugs separated by commas. `build_topic_indices.py` parses this regex: `^## Problem (\d+)\s*\n\s*\*Tags:\s*(.+?)\s*\*`
- `---` horizontal rule between problems (not after the last one)

## Tag slugs

**Topics are narrow — specific techniques, formulas, or theorems, not broad areas.** The point is that someone can practice every AMC/AIME problem that uses, e.g., Vieta's formulas and internalize that one idea. Broad tags like `algebra` and `geometry` exist only as **fallbacks** when no narrow technique is detected in a problem's solutions.

The authoritative list of tag slugs lives in `TAG_PATTERNS` at [scripts/retag.py](scripts/retag.py). Slug rules:

- Lowercase, hyphenated
- Apostrophes stripped (`vietas-formulas`, not `vieta's-formulas`)
- Named after the technique, not the area (`power-of-a-point`, not `geometry-circles`)

The full current list is indexed in [topics/README.md](topics/README.md), which is regenerated by `build_topic_indices.py`.

**Adding a new tag:**
1. Add its slug + detection regex(es) to `TAG_PATTERNS` in `scripts/retag.py`
2. Rerun `python scripts/retag.py` to apply it to existing problems
3. Rerun `python scripts/build_topic_indices.py` to regenerate topic pages (the new page auto-creates)

**Adding a tag by hand to one problem:** just edit the `*Tags:*` line in the exam file and run the indexer. `retag.py` won't overwrite your manual tags unless you rerun it.

## Competition directory conventions

| Competition | Directory | Filename | Problems per exam | Variant history |
|---|---|---|---|---|
| AMC 8 | `problems/amc8/` | `<year>.md` (e.g. `2023.md`) | 25 | Never had variants |
| AMC 10 | `problems/amc10/` | `<year>[A\|B].md` | 25 | 2000–2001 single (`2001.md`); 2002+ A/B (`2023A.md`, `2023B.md`) |
| AMC 12 | `problems/amc12/` | `<year>[A\|B].md` | 25 | Same split as AMC 10 |
| AIME | `problems/aime/` | `<year>[I\|II].md` | 15 | 1983–1999 single (`1985.md`); 2000+ I/II (`2023I.md`, `2023II.md`) |

The filename stem (`2023A`, `1985`, `2023I`, etc.) is what `build_topic_indices.py` parses via `^(\d{4})([A-Za-z]*)$` to extract year and variant. Keep the pattern.

## Scripts (`scripts/`)

- **`fetch_exams.py`** — scrapes AoPS wiki, writes exam .md files. Uses Python stdlib only (no deps). Rate-limited at 0.5 s per request. Probes Problem 1 before a full exam fetch and silently skips exams that don't exist on AoPS (so `--years 1985-2024` is safe on any competition). Default variants include `""` for competitions with a pre-split era (AMC 10/12 before 2002, AIME before 2000). Initial tag assignment uses keyword heuristics on the **problem** text and is coarse — follow with `retag.py`.
- **`retag.py`** — rewrites every problem's `*Tags:*` line based on regex patterns in `TAG_PATTERNS` applied to **solution** text. This is where narrow technique tags come from. Scans solutions because authors explicitly name techniques in solutions ("By Vieta's...", "Applying the law of cosines...") but almost never in problem statements. Falls back to broad-area tags when no narrow match.
- **`build_topic_indices.py`** — globs `problems/**/*.md`, extracts tags, rewrites topic tables between AUTOGEN markers, and regenerates `topics/README.md` as an alphabetical index of all topic pages.

**AoPS API endpoint used:**
```
https://artofproblemsolving.com/wiki/api.php?action=parse&page=<PAGE>&format=json&prop=wikitext&redirects=1
```

Page naming on AoPS:
- Exam index: `2023_AMC_10A_Problems`
- Per-problem: `2023_AMC_10A_Problems/Problem_1` (redirects are common for problems shared between AMC 10 and AMC 12)
- AIME: `2023_AIME_I_Problems/Problem_1`

**Markup conversions in `fetch_exams.py`:**
- `<imath>X</imath>` → `$X$`
- `<math>X</math>` → `$X$`
- `<math display="block">X</math>` → `$$X$$`
- `<cmath>X</cmath>` → `$$X$$`
- `<asy>...</asy>` → placeholder (Asymptote doesn't render in Markdown)
- `[[Image:...]]` → placeholder

## Tag heuristic caveat

Both `fetch_exams.guess_tags()` (broad fallback) and `retag.py`'s `TAG_PATTERNS` (narrow primary) are regex-based keyword classifiers. They'll have false positives and false negatives. Known quirks:

- `fetch_exams.guess_tags()` deliberately ignores `integer`, `prime`, and `square` alone, because AMC/AIME problems use those as stock phrases (`relatively prime positive integers`, `perfect square`).
- `retag.py` casts a wide net — tags like `floor-function` trigger on any `\lfloor`, `casework` on `Case 1:`, `modular-arithmetic` on any `\pmod`. Expect many problems to pick up multiple narrow tags from long solution sections.
- Broad-area fallback kicks in only when NO narrow tag matches. It can still misclassify — e.g. a counting problem phrased as "find the number of subsets" falls through to `algebra` because it lacks counting keywords.

**Fix by hand, not by tweaking heuristics unless absolutely necessary.** Edit the `*Tags:*` line inside the exam file, then rerun `python scripts/build_topic_indices.py`. `retag.py` overwrites hand edits — only rerun it on problems where the automatic tags are all wrong, or after modifying `TAG_PATTERNS`.

## When adding an exam from AoPS

1. `python scripts/fetch_exams.py <competition> --years <year> [--variants <letters>]`
2. `python scripts/retag.py problems/<competition>` — replace the coarse fetch-time tags with narrow technique tags
3. Open the generated file under `problems/` and audit each problem's `*Tags:*` line
4. `python scripts/build_topic_indices.py`
5. Commit

## Things not to do

- Don't amend the AUTOGEN block by hand — your edits will be wiped on the next indexer run.
- Don't rename `## Problem N` headings (breaks topic-page links).
- Don't introduce a parallel `solutions/` tree — solutions go inline with problems.
- Don't hand-maintain topic tables — let the indexer do it.
- Don't use broad-area tags (`algebra`, `geometry`, `number-theory`, `combinatorics`, `probability`, `sequences-and-series`, `trigonometry`) as the primary tag for a problem. They exist only as a fallback when no narrow technique applies. Prefer specific techniques.
- Don't rerun `retag.py` after hand-editing tags — it will overwrite your manual corrections. Only rerun it on specific subdirectories you want refreshed, or after updating `TAG_PATTERNS`.

## Environment

- Python 3.10+ (uses `|` type union syntax)
- No third-party deps — stdlib only
- Platform: Windows (paths use forward slashes in scripts for cross-platform)
